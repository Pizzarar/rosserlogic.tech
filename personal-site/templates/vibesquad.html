An app for running a squad of AI coding agents. You bring the ideas; it keeps them sorted, keeps each agent in its own lane, sends work to the right model, and checks the work before it gets to you.

Version 0.3.0 is on the stable channel (released Nov 12, 2026), for Windows: a desktop app and a local web UI, with a phone cockpit you can pair over your LAN or a VPN mesh. The Android app is not part of that release. Read the interactive tour of how it works or the v0.3.0 release.

What's new in 0.3.0

  • Breaking: agents now identify themselves with a per-agent token that the runner injects. Scripts that call vs or the VS API with an agent id but without the token get a 403.
  • Cookie-authenticated writes need a same-origin proof, and phone pairing uses a two-step confirm.
  • Phone Cockpit has a settings overlay and a one-tap Claude and Gemini provider switcher. The end-to-end encrypted relay is wired in but off by default.
  • Boring Mode: an app-wide plain layout, card-grid dashboards, a compact header and a first-launch layout picker.
  • Restarts no longer cut or wedge running agents, and the new vs watch command sends one ping per set of items.
  • Windows only. The Android app is not part of this release.

How it works

  1. 1You + Brainstorm

    You've got ideas. You talk them through with your brainstorming buddy, and anything off-topic gets parked so nothing derails.

  2. 2Lead + Workers

    The buddy hands the plan to the lead, who splits it into separate git worktrees and routes each piece by stakes: top models at high effort for security and core-invariant work, smaller models for mechanical work. Reviews go to a different model family, and each review has to say whether a change fixes the cause or only hides the symptom.

  3. 3Back to you

    When something needs your call, your phone pings. You say yes or no.

In development since v0.3.0

Four things on the main branch that are not in the v0.3.0 download above. This is the current development build, so details can still change.

DEV BUILD

Role and stakes routing

Every spawn carries a stakes label: security, invariant, normal or mechanical. The label picks a model and effort from a per-provider ladder, so mechanical work goes to a cheap, fast model and top-tier work (security and core invariants) goes to a top-tier model at high effort.

Roles map to tiers (top, mid, cheap), and each role has a provider order that is walked when a provider is capped. A local file can override the ladder.

The lead sets the stakes label; the task is not classified automatically.

DEV BUILD

Server-attested review verdicts

A reviewer's verdict is one line: PASS or FAIL, three counts and the commit reviewed. The server records it, and counts it as attested only when the entry comes from a reviewer.

With the push guard installed, merging a unit branch into main needs a recorded PASS for the exact commit at the branch tip. Reviews go to a different model family by default.

Cross-family review is the default routing, not a hard rule. What the code enforces is the recorded PASS.

DEV BUILD

Headless Linux host, Phone Cockpit and Usage view

A bootstrap script sets up a Debian or Ubuntu box as an always-on host: a systemd user service, linger enabled, sleep masked, Node installed and the app built. It is a Linux build of the same server, no desktop session needed.

The Phone Cockpit now has a full-screen Usage dashboard, opened from its menu drawer or the quota banner.

Pairing over your LAN or a VPN mesh works out of the box. An optional end-to-end-encrypted relay (Noise-style channel, X25519 and AES-GCM) can let a phone reach the host without opening ports; it is off by default.

DEV BUILD

Code | Storybook tabs and Playtest Overlay

For game projects, a Code | Storybook switch sits at the top of the project view. Storybook is a read-only overview of the game's quest web, locations, characters and findings.

The Playtest Overlay is a Godot 4 addon. It docks a chat beside the running game, and its bug button captures a screenshot, the node under the cursor, scene, state, seed, logs and build hash and sends them to a squad. It is owner-only and local-only. Agents can also inspect a running Godot game through a runtime debug bridge.
